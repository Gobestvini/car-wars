# Работа над новой игрой

Сначала прочитай README.md и выбери подходящий локальный навык через `.agents/skills/find-skills/SKILL.md`. Каталог сети и установка нужны только при пробеле в доступных навыках; перед установкой проверь источник и содержимое. Подходящие навыки разрешено устанавливать локально в `.agents/skills/` без повторного подтверждения.

## Контекст и задачи

- Для реализации читай только нужные файлы; карта — `docs/PROJECT.md`. Актуальные подсказки: `pnpm context -- "запрос"`. Подсказки и документы не заменяют проверку кода.
- Для задания другой модели применяй локальный `create-task` и соглашения `docs/tasks/README.md`. Подготовка задания не означает реализацию или создание чата.
- Задание из `docs/tasks/` читай целиком, проверяй актуальность и зависимости, соблюдай границы. Обновляй отчёт и INDEX. `done` означает выполнение всех обязательных критериев; недоступную проверку обозначай явно.
- Одна задача — один наблюдаемый результат. Не добавляй соседние рефакторинги. Краткий запрос не требует большого плана и новой задачи без необходимости.
- Подключай `game-quality` для игровой логики, управления, ресурсов и производительности; `ai-economy` — для объёмной реализации и передачи контекста. Остальные документы открывай по потребности.

## Проверки и завершение

Команды запускай из корня этой папки. Для кода — релевантные тесты и сборка; для интерфейса — браузерная проверка изменённого поведения. Финальные тесты и сборка: `pnpm check:full`; `pnpm check` использует квитанцию только при совпадении входов. Квитанция не заменяет браузер, реальные устройства и критерии задачи. Логи остаются на диске; в чат извлекай итог и строки ошибки.

Новые тесты должны проверять поведение и регрессии. Косметическая правка не требует зеркальных тестов. Не редактируй node_modules или dist. Не выдавай headless/emulation за проверку реального телефона. Не публикуй игру и не запускай Telegram без запроса.

После выполнения запроса и обязательных проверок создай коммит только со своими изменениями и отправь текущую ветку в настроенный remote. Не включай чужие изменения. При ошибке push сохрани локальный коммит и укажи причину. У нового проекта сначала должен быть настроен собственный Git remote.
