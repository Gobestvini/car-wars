# Опциональная AI-очередь через Telegram

Перенесён работающий подход исходного проекта: личная привязка, долговременная очередь, отдельный worktree, планировщик → исполнитель → один помощник при сбое, структурированный результат, тесты/сборка, коммит и push. Listener не запущен и учётные данные не перенесены.

Используй только после копирования шаблона в отдельный Git-репозиторий с первым коммитом, собственным remote, чистым кодом, установленными зависимостями и авторизованным Codex CLI. Во вложенной папке CarWars runner остановится до создания worktree. CI проверяет код, но не публикует игру.

## Настройка

1. Создай собственного Telegram-бота. Скопируй `.telegram-bot.env.example` в локальный `.telegram-bot.env` и задай токен. Для `/game` задай GAME_URL.
2. При необходимости укажи AI_PLANNER_MODEL, AI_WORKER_MODEL, AI_HELPER_MODEL, доступные в твоём аккаунте. Пустые значения сохраняют исходную схему моделей; совместимость проверяется в твоей среде, она не обещается шаблоном.
3. Выполни `pnpm telegram:check`: это локальная проверка наличия токена без обращения к API.
4. По явному запросу запусти `powershell -File .\tools\telegram\start.ps1`; для фона добавь `-Background`. Выполни `/pair CODE` из локального журнала в личном чате. Остановка: `powershell -File .\tools\telegram\stop.ps1`.

Команды: /help, /status, /tokens, /game, /pause, /resume, /reply ID ТЕКСТ. Текст создаёт запрос; фото с подписью передаётся исполнителям. Pause не прерывает текущую работу. При аварии running становится interrupted и автоматически не повторяется. Watchdog контролирует listener без вызовов модели; автозапуск Windows не настраивается.

Запуск listener разрешает обработку входящих запросов владельца, вызовы моделей и автоматический commit/push по ним. Runner использует Codex CLI без интерактивных approvals с доступом к файлам; запускай в предназначенной для этого среде. Секретный Telegram env не передаётся моделям. Состояние, логи, квитанции и worktree исключены из Git. Скрипты не отправляют сообщения, пока listener не запущен.

## Проверки и расход

Для обычных мелких изменений прямой чат экономнее полного pipeline. Сложные запросы получают ограниченные инструкции и актуальную память. Учёт /tokens разделяет input, cached input, output и reasoning; неизвестные значения обозначены явно. Доступность/стоимость модели не выводится из usage.

Публикацию результата контролирует runner после отчёта done и автоматических проверок; ручные критерии остаются обязанностью исполнителя. При изменении основного HEAD/ветки перенос остановится и сохранит результат в рабочей ветке; ошибка push сохраняет локальный коммит. Полные журналы находятся в tools/telegram и .telegram-check-logs.
