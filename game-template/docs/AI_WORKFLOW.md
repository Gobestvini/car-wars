# Качество при небольшом расходе контекста

## Рабочий цикл

1. Уточни наблюдаемый результат и обязательные проверки. Если задача проста, работай напрямую.
2. Прочитай AGENTS, задание и краткую карту; выбери локальный навык. Сетевой поиск нужен при отсутствии подходящего навыка или необходимости проверить актуальный факт, а не как повторяемая церемония.
3. Получи ограниченную актуальную память: `pnpm context -- "тема"`. Затем `rg` по символам и чтение нужных диапазонов. Не открывай историю задач, каталоги видео, lockfile и полные логи по умолчанию.
4. Сделай один законченный срез, проверь обязательные сценарии и запиши результат, ограничения и точные команды.
5. Обнови задачу/карту/память только там, где появился полезный новый факт. Заверши своими commit/push.

## Выбор исполнителя

| Работа | Подход |
| --- | --- |
| Локальная правка с ясным контрактом | Прямая реализация; простая модель при достаточном качестве |
| Несколько модулей, пограничные случаи | Средняя модель, ограниченное задание |
| Неизвестная архитектура, сложная физика, повторный сбой | Сильная модель для снятия конкретной неизвестной |

Разделение «планировщик → исполнитель → помощь» полезно при передаче сложной работы; для мелкой правки три запуска могут стоить дороже одного. Один содержательный повтор после диагностики предпочтительнее бесконечных попыток. Точные модели и доступность выбираются в среде проекта; экономия не гарантируется названием модели.

## Проверки без повторного расхода

`pnpm check:full` выполняет тесты и сборку, пишет полные логи в `.telegram-check-logs/` и квитанцию `.telegram-checks.json`. `pnpm check` повторно использует успех только при совпадении кода, тестов, настроек, lockfile, установленных версий и среды Node. Изменение только отчёта не требует ещё одной сборки. Новые ошибки, изменение кода или неполный критерий требуют проверки.

Квитанция не кэширует ручное ощущение управления, screenshots, сетевые отказы, физический телефон и производительность. Эти проверки фиксируются отдельно по задаче. Не перечитывай stdout целиком: итог, код возврата и релевантные строки достаточны для контекста.

## Память и измерение

Храни короткие факты с source hashes, датой и видом evidence. Старый отчёт с несовпавшими хэшами исключается. Память не подтверждает все возможные сценарии. Не сохраняй секреты, env, картинки и сырые логи.

Учёт usage находится в `tools/telegram/economy.js`: cached input входит в input, reasoning входит в output, неизвестное usage не равно нулю. Не складывай вложенные показатели повторно. Сравнивай общее input/output по сопоставимым завершённым задачам вместе с числом повторов и дефектов. Сокращение текста инструкций само по себе не доказывает экономию.
