# Telegram → задания → разработка → QA

Telegram listener теперь только подготавливает задания по тезисам через локальный create-task. Планировщик gpt-6.1-sol читает актуальный checkout в sandbox read-only и возвращает структурированный документ. Бот проверяет пути, уникальные ID, статус, зависимости, отчёт исполнителя и строку INDEX; сохраняет только новые TASK-файлы и INDEX, коммитит и отправляет их. Исходники, реализация, QA и публикация игры в этом маршруте не запускаются.

`ready` — задание доступно разработчику. `draft` — нужен ответ или завершение зависимости; оно не запускается автоматически. При blocked ответьте боту `/reply ID тезисы`. Это новое планирование; старые ветки/worktrees и незавершённая реализация не переносятся автоматически. `/pause` и `/resume` управляют только созданием заданий. `/status` читает актуальные статусы подготовленных файлов. Старые запросы и worktrees сохранены для ручного разбора.

Часовые автоматизации привязаны к текущему чату Codex:

- Разработка — в начале каждого часа, роль [game-frontend-developer](roles/game-frontend-developer.md), одна задача.
- QA — на 15-й минуте каждого часа, роль [game-qa](roles/game-qa.md), одна готовая задача.

Обе используют `node tools/tasks/queue.js claim dev|qa` и общую локальную блокировку. QA пропускает слот, если разработчик ещё работает; задача попадёт в следующий доступный слот. Выбор — приоритет, затем ID; зависимости читаются из файла задания и должны быть done. Статус в INDEX не используется как доказательство готовности. Возврат QA отмечается in-progress и метаданными «Возврат QA: да». После исправления снова ready-for-qa. done выставляет независимый QA.

Пустая/занятая очередь не требует уведомления. Сообщение нужно при завершении, дефекте, сбое или необходимости решения. При аварии lock остаётся; сначала проверьте незаконченную работу, затем освободите блокировку её token. Автоматически снимать lock через час нельзя: задача может выполняться дольше.

Для работы локальных расписаний компьютер и Codex должны быть запущены, проект доступен. Запуск/остановка Telegram listener по-прежнему через `tools/telegram/start.ps1 -Background` и `tools/telegram/stop.ps1`; watchdog не выполняет задачи и не вызывает модели. Изменения кода бота требуют перезапуска listener.

## Основание для ролей

Роль описывает специализацию, контекст, границы, контракт передачи и проверяемый результат. Одно название профессии не заменяет эти инструкции. Принятые здесь решения — адаптация рекомендаций к CarWars, а не гарантия качества от «ролевого» промпта.

- [OpenAI: Best practices](https://learn.chatgpt.com/guides/best-practices) — контекст репозитория, устойчивые инструкции, навыки и проверка результата.
- [Anthropic: Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) — простые составные workflows и отдельная оценка с обратной связью (evaluator-optimizer).
- [DeepLearning.AI: Agentic AI](https://www.deeplearning.ai/courses/agentic-ai) — планирование, reflection, инструменты и evaluation; обзор программы найден в поиске, полное содержимое курса не проверялось.

Выделение игровой специализации, конкретные часы, файловая блокировка и передача через ready-for-qa — решения для этого проекта. Файлы ролей явно указаны в промптах автоматизаций; они не загружаются как AGENTS.md автоматически.
