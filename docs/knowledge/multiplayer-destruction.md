# Онлайн: кузов, тротуарные объекты и джойстик

## Актуальное дополнение 2026-10-19: короткий ghost вместо физического обломка

TASK-0108 меняет описанную ниже прежнюю семантику обломков. Признак: сбитые предметы продолжали блокировать/толкать машины и в конце уменьшались в размерах. Причина: `detach()` заменял статическое тело динамическим на 5 с, а visual.sync трактовал fade как масштаб. Рабочий способ: оставлять исходное тело только как носитель позы вне World, `byBody` и `activeIntact`; ту же инварианту соблюдать при `restoreStreet()`. Начальная alpha=0.45, линейное исчезновение за 0.75 с симуляции, без масштабирования и полёта. Пороги разрушения/события сохранены. В offline main явно включена регистрация деревьев, как уже было в online manifest; scene-only fixtures сохраняют прежний необязательный флаг.

Целые предметы остаются instanced. `StreetPropFadePool` создаёт proxy только для сбитых экземпляров: геометрия/текстуры общие, материалы независимы, instanceColor переносится в proxy. Active и idle ограничены 24 записями каждый; собственные материалы освобождаются при dispose, общую geometry proxy не уничтожает. Включены урна/скамейка/фонарь/светофор/дерево со всеми частями. Уничтоженный светофор остаётся погашенным.

Семантика detached изменена при прежней форме wire state: presentationVersion/motionVersion=5, mapVersion=3, binary frame format без изменения. Старый presentationVersion=4 должен получить требование обновления. Не принимать новый клиент на старом публичном сервере за проверку новой серверной физики.

Проверка 2026-10-19: целевые world-step, restore/replay, independent-alpha и bounded-pool тесты; реальный Edge WebGL offline на 1440×900/390×844, high/low, все пять типов выше/ниже порога, повторные reset/rebuild и лимит 24; три 3D-клиента с настоящими серверными ударами, поздним входом detached/removed и reconnect. [Offline отчёт](../knowledge/street-props-0108/report.json), [online отчёт](multiplayer/2026-10-19-props/report.json). Для сравнительных кадров ghost-поза/симуляционный возраст удерживались операторской фикстурой после настоящего удара; это визуальное подтверждение формы/alpha, не измерение сетевой задержки. Физический телефон и публичная выкладка не проверялись. Независимая QA-приёмка записывается в файлах задач.

Неудачный приём при проверке: изменение импортируемого JS во время браузерной матрицы вызывает Vite reload и уничтожает execution context. Завершать либо перезапускать матрицу после изменения исходников; такой сбой фикстуры не считать дефектом игровой логики и не записывать незавершённый прогон как успешный.

Сильный удар после 0108 освобождает проезд, но целый предмет при слабом контакте способен удерживать NPC. Это отдельно воспроизведено в online/offline и исправлено ограниченным безопасным retreat в TASK-0109; [причины, сравнение до/после и ограничения](multiplayer/2026-10-19-npc-liveness/README.md). Предмет ниже порога сохраняет коллизии. Собственная модель NPC не становится ghost и не исчезает.

2026-10-18. Признаки: после переноса в online пропали вмятины и сносимые
декорации, ручка джойстика оставалась в центре при работающем управлении.
Причина: отдельный online renderer подключал только скаляр damage/дым, создавал
город без StreetPropPhysics и не обновлял transform ручки в pointermove.

Рабочий способ:

- Сервер хранит до 32 локальных ударов кузова на поколение машины, как офлайн
  CarDeformation. Полные motion frames передают историю, поэтому поздний вход
  видит те же вмятины. Смена generation очищает только кузов этой машины.
  Геометрия клонируется для каждого игрока; повторные кадры не повторяют удар.
- Подписанная карта v3 включает серверный manifest фонарей, урн, скамеек,
  светофоров и деревьев. Проверяется точное совпадение с placement/render IDs.
  Общий StreetPropPhysics считает удары и обломки на сервере и в prediction.
  Каждый полный кадр несёт состояния detached/removed; intact подразумевается.
  Это ограниченный размер состояния, а не бесконечный журнал событий.
- Rewind восстанавливает p/q/v/av, возраст обломка и жизненный цикл. После пяти
  секунд обломок исчезает, removed ID сохраняется до закрытия комнаты. Визуальный
  registry перемещает исходные instance slots, включая кроны деревьев, и гасит
  разрушенный светофор. Replay не пишет повреждения кузова на клиенте.
- Ручка использует существующие knobX/knobY joystickVector. Новый жест центрирует
  ручку; второй палец/правая кнопка не захватывают управление, чужой pointerup
  не сбрасывает активный жест.

Проверено локально: 74 целевых теста (включая 7 новых), сборка Vite; отдельно
настоящие три SDK-клиента: удары, поздний вход с вмятинами/сбитой урной, исчезновение
обломка, независимый respawn, обрыв и автоматическое переподключение. Тест reconnect
ждёт минимальные 5 секунд существования клиентского соединения, требуемые SDK.

Три настоящие 3D-вкладки в операторской localhost-фикстуре показали одинаковые
11/2/0 ударов и 2436/894/0 изменённых вершин трёх кузовов, два уничтоженных объекта,
577 зарегистрированных объектов, frame p95 около 16.8 ms. Ошибок console error
нет. Реальный drag (100, -60) px дал transform ручки (54.8796, -32.9277) px,
то есть ограниченный существующим радиусом 64 px. Это проверка мышью в desktop
браузере; физический сенсорный телефон не проверен.

Доказательства: [browser-local.json](multiplayer/2026-10-18-destruction/browser-local.json),
[кадр с вмятиной](multiplayer/2026-10-18-destruction/three-clients-dents.png).
Операторская фикстура `browser-destruction-probe.js` слушает только localhost и не
подключается production entrypoint; публичного API перестановки машин нет.

Ограничения: сервер остаётся preview-миром; полиция/розыск/аптечки ещё не перенесены.
Дома не разрушаются. Постоянного сохранения комнаты после рестарта нет.
Физический replay обломков проверен с допуском 2.5 cm/0.2 m/s на коротком
интервале: смена порядка контактов Cannon при пересоздании тел может давать небольшие
расхождения, которые исправляет сервер. Не выдавать это за побитовую детерминированность.

## Стоимость prediction на ARM64

Первый кандидат не выкладывался: реальный TCP netem дал headless p95 порядка
78–108 ms даже после замены полного обхода props на changedEntries/episodes.
Профиль Node показал основную стоимость в CityBroadphase.aabbQuery/collect и GC.
Маска лучей подвески раньше применялась Cannon только после сбора/сортировки
кандидатов. CityBroadphase.raycastClosest теперь временно применяет ту же маску
до сбора кандидатов и восстанавливает её в finally. Обычные AABB-запросы и пары
контактов остаются без этой дополнительной фильтрации.

Проверка: одинаковые body/hitPoint/normal с родным SAP на трёх осях, одинаковая
траектория/скорость кузова и подвески за 1200 шагов; исключение raycast не оставляет
маску включённой. Отдельные коллекции changedEntries/episodes исключают полный
обход сотен целых объектов на каждом replay step; registry хранит стабильные
индексы, а не ссылки на старый физический мир после reconnect.

Последовательный 40-секундный netem: 75 ms + jitter 10 ms + loss 1% с каждой
стороны, отдельные процессы (сервер 1.5 CPU; клиенты по 1 CPU), 102 NPC / 3 игрока.
Текущий старый релиз dc4f4b0 в тех же условиях: server 119.36 Hz, headless p95
43–52 ms. Финальный код a9fc8ae: server 119.88 Hz, headless p95 48–53 ms.
Это сопоставимо по этому короткому стресс-прогону, а не доказательство отсутствия
рывков на любом устройстве: редкая максимальная коррекция достигала 1.97 m.
[Числа и ограничения](multiplayer/2026-10-18-destruction/netem.json).

Не запускать CPU benchmark одновременно с полной функциональной приёмкой на
том же VPS: первый такой прогон дал ложные wall-clock timeout/недостаток шагов.
Изолированный повтор SDK destruction прошёл; итоговая приёмка запускается
последовательно после netem. Не увеличивать timeout вместо проверки нагрузки.


## Публичная выкладка и итоговая проверка

Сервер a9fc8ae активирован 2026-10-18, контейнер healthy. На том же ARM64 образе
последовательно после netem прошли все 76 целевых тестов. Публичный SDK smoke
прошёл: 3 клиента/102 NPC, одинаковая карта, лимиты комнаты/сервера, движение,
