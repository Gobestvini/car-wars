# Краткая память агентов

Перед поиском по всему проекту используй контекст, который Telegram runner добавляет в запрос. Для ручной работы: `node tools/telegram/knowledge.js "текст задачи"`. Общие инженерные правила остаются в `../playbook.md`; большие каталоги источников не нужны для каждой правки.

`memory.json` хранит короткую карту модулей и результаты завершённых задач. Каждая запись связана с SHA-256 исходных файлов. При изменении или удалении файла запись исключается из подсказок. Отсутствие записи означает необходимость проверить нужный код, а не повторить всю историю исследований. Данные памяти не заменяют требования пользователя, чтение задания и проверки.

Для текстовых исходников CRLF нормализуется в LF перед хэшированием: Git worktree может иметь другие окончания строк без изменения кода. Для двоичных файлов хэшируются исходные байты.

Runner автоматически записывает итог исполнителя только после тестов и сборки. Итог помечен как отчёт исполнителя: он не доказывает все сценарии поведения. Поиск выбирает до восьми актуальных записей, максимум 6000 символов; хранится до 40 результатов плюс основная карта. Секреты, окружение и полные логи сюда не попадают. При ручном добавлении записей сначала проверь источники и обнови их хэши.

Для финальных автоматических проверок выполняй `node tools/telegram/verify.js --full`. Он сохраняет полные логи вне контекста и квитанцию `.telegram-checks.json`. Runner повторно использует её только при тех же исходниках, тестах, настройках, зависимостях и версии Node. Изменение отчёта задачи не требует нового запуска игровых тестов. При изменении кода квитанция недействительна. Обязательные ручные и браузерные проверки выполняются отдельно согласно задаче.
