# NPC traffic: исследование и выбранный план

Дата проверки источников и runtime trace: 2026-10-06. Цель этого документа — зафиксировать узкий план для текущих 60–300 городских машин, а не описать универсальную дорожную симуляцию. Это ADR для TASK-0035/0036; production AI этим исследованием не менялся.

## Решение

Сохранить единый Cannon world для ближних NPC, существующие 10 Hz AI decisions, 120 Hz physics step и логический LOD вдали. Не внедрять внешний SUMO/CARLA runtime и не заменять текущий AI полным IDM/MOBIL. Заимствовать safety-проверки и разделение стадий: snapshot → hazard/insertion assessment → decision → controls → physical integration. Для дальних логических машин используются те же candidate-gap, signal и junction decisions, только движение интегрируется kinematic шагом.

Минимальный объём:

1. **Безопасная вставка (TASK-0035).** До создания NPC проверить oriented vehicle footprint против игрока, всех физических/логических автомобилей, зданий и дорожных границ. Между бамперами оставить не менее2м; при движущемся соседе требовать ещё и тормозной запас по относительной скорости. Использовать ограниченный deterministic поиск свободных directed-edge slots; заявки без свободного места оставить pending с причиной и небольшой фиксированной retry quota на шаг. Reset сначала строит новый согласованный набор слотов, затем размещает его; увеличение количества не двигает уже едущие машины. Добавление физического body и перевод LOD выполняют ту же footprint-проверку.

2. **Продольное следование.** Сохранить существующий safe-speed закон `sqrt(v_leader² + 2*b*gap)`, но заменить фиксированные6.2м между центрами на oriented bumper gap вдоль текущей полосы/пути и учитывать скорость сближения. Начальные параметры для проверки: минимальный bumper gap `s0=2м`, time headway `T=0.8с`, planner deceleration `b=5.5м/с²`, ограничение скорости города8.5м/с. Для сигнала использовать стоп-плоскость от TASK-0033 и передний габарит кузова. Bounded IDM/ACC может быть эталонным сравнением в unit fixture, но сначала не переносить полные параметры highway-калибровки: плотная городская сетка, 50м блоки и малые скорости CarWars отличаются от highway benchmark.

3. **Прогресс и очередь перекрёстка.** Измерять signed progress по текущему направленному ребру, а не евклидово расстояние до узла. Таймер потери прогресса растёт при менее0.2м продвижения за1с только если машина не имеет законного wait reason; после3с запускается повторный поиск пути/коридора. На въезде проверять keep-clear footprint на выходном ребре минимум на длину машины4.16м плюс2м. Reservations выдавать по `(время ожидания с момента запроса, стабильный ID)`; существующий `entered` резерв освобождать только когда задний бампер вышел из conflict region. Timeout сам по себе не передаёт конфликтный перекрёсток другой машине.

4. **Локальный объезд и recovery.** Сохранить arcade route follower, но тестировать весь временной коридор перестроения и возврата, не только поперечную позицию. Проверять swept oriented footprint при горизонте до3с для ведущих, задних и встречных автомобилей; принимать только манёвр с безопасным return path и свободным legal road corridor. Добавить cooldown2с и общий deterministic yield priority (старший wait age, затем ID); ожидающая в сигнал/очередь машина не объезжает очередь. При отсутствии коридора продолжать объяснимое ожидание с повторной оценкой раз в0.5с. Не телепортировать машину и не отключать контакты.

5. **Единая decision snapshot и diagnostics.** На decision tick один раз собирать позиции, скорости, yaw, footprint, LOD mode, path progress, leader/blocker, signal, reservation age. Строить локальные кандидаты существующей пространственной сеткой12м; сначала принимать intent всех машин на одном snapshot, разрешать конфликты stable priority, затем публиковать controls. Controls задают steer/throttle/brake; не сдвигают физические тела. Diagnostics оставляют `state`, `waitReason`, `blocker`, `noProgressTime`, `logical`, signal и reservation age доступны test trace.

FSM в пределах этой реализации: `following` → `signal-wait | queue-wait | yielding` → `following`; после локальной потери прогресса `maneuver` либо `recovery-wait`; по открытому безопасному маршруту возврат в `following`, иначе периодически перепроверяемое `blocked-no-safe-route`. `following` с околонулевой скоростью не считать нормальным состоянием без причины.

## Источники (проверены 2026-10-06)

- [SUMO Vehicle Insertion](https://sumo.dlr.de/docs/Simulation/VehicleInsertion.html): insertion проверяет полный передне-задний footprint, leader и follower safety и остановки на маршруте; небезопасная/невозможная вставка откладывается в очередь. Основание allocator queue для CarWars; SUMO dependency/teleporting сюда не переносить.
- [Treiber, IDM and variants](https://traffic-simulation.de/info/info_IDM.html): longitudinal following принимает собственную скорость, bumper gap и closing speed; красный сигнал можно представить stationary obstacle у stop line; интегратор обязан корректно удержать нулевую скорость, не создавать движение назад. Основание для gaps/closing speed и signal hazard, но значения/highway модель не копировать автоматически.
- [Treiber, MOBIL lane-change model](https://traffic-simulation.de/info/info_MOBIL.html): смена требует safety condition для задней машины новой полосы и incentive; порог и cooldown нужны для предотвращения lane hopping. Для CarWars берём safety/cooldown, но не полный politeness/incentive расчёт для однополосного узкого объезда.
- [SUMO Intersections](https://sumo.dlr.de/docs/Simulation/Intersections.html): keep-clear эвристика не пускает в junction, если очередь/занятый выход оставит автомобиль внутри перекрёстка. При этом SUMO документирует teleport/ignore blocker recovery; CarWars вместо них оставляет физические столкновения и явное ожидание.
- [CARLA Traffic Manager](https://carla.readthedocs.io/en/latest/adv_traffic_manager/): разделяет localization/path buffer, collision forecast, traffic-light hazard, motion planning и apply-control; использует протяжённые вдоль прогнозного пути bounding boxes. Основание snapshot → hazard → decision → controls; внешний движок не нужен.
- [SUMO Safety](https://sumo.dlr.de/docs/Simulation/Safety.html): безопасный gap зависит от headway и action/reaction step; короткий headway относительно update step повышает риск контакта. Наш fixed physics dt=1/120с не равен AI decision cadence0.1с: тесты должны проверять decision lag отдельно.

Критерии источников: это официальные документации SUMO/CARLA и страница разработчика IDM/MOBIL; они описывают модели, не доказывают что параметры оптимальны для CarWars. Все выводы о проекте проверяются собственными trace/tests.
