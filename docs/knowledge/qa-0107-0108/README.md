## Выявленный дефект TASK-0107

Одинаковые position/target не гарантируют одинаковую экранную композицию.
`src/main.js:resize()` задаёт фактический offline FOV=50°, а online оставляет 38°.
На всех трёх viewport при 0 и 110 км/ч экранная длина одинакового кузова online
равна offline × 1.3542557732. На 1440×900 в покое: 85.2619 против 115.4665 px.
Доказательство — `compositionMismatches` в spot-report и парные игровые PNG.
Задача должна вернуться разработчику с сохранением фактического offline-эталона.

## Проверенные приёмы и неудачные фикстуры

- Признак: `modelReady=true`, но игровой PNG закрыт загрузочным экраном. Причина:
  loading.finish снимает overlay позже, по таймерам. Рабочий способ: дождаться
  `document.body.dataset.loading==='false'` и скрытого `#loading-screen`, а затем
  проверить игровой кадр глазами. Подтверждено этими PNG 2026-10-19. Ограничение:
  modelReady продолжает быть полезным отдельным условием готовности модели.
- Признак: сравнение касательной позиции/цели прошло, но масштаб кузова различен.
  Причина: effective FOV меняет resize после initializer. Рабочий способ: читать
  текущий FOV и сравнивать экранную проекцию одной позы после resize, дополнительно
  смотреть пары кадров. Подтверждено на 6 парах 2026-10-19; это ошибка текущего
  online-клиента, а не предложение нового ракурса.
- Неудачная первая NPC-фикстура давала timeout: выбранный дальний NPC находился в
  logical-режиме вне World и после телепорта возвращался на маршрут. Для проверки
  физического удара операторская фикстура должна установить physical=true и
  добавить его существующее тело в World; после этого реальный контакт прошёл.
  Это исправление фикстуры, не продуктовый дефект и не проверка NPC AI.
- При остановке offline stepper нужно завершить VehicleAppearance существующим
  cancelPlayerAppearance(), иначе управление остаётся заблокированным появлением.
  Повтор touch-жестов вверх/вправо после этого дал одинаковые steer/throttle/brake
  в online и offline. Эта фикстура не заменяет физический сенсорный телефон.
- Для проверки выхода/новой комнаты использовать игровой UI (`online-share` →
  `online-leave` → `online-create`): прямой внутренний network.leave() отключает
  transport, но намеренно не выполняет обязанности внешнего UI-обработчика.
  Первая попытка нажать create после внутреннего leave дала timeout фикстуры;
  проход через UI подтвердил восстановление intact в новой комнате.
