# Online client lifecycle

Source: TASK-0099 implementation and Node/SDK/browser checks,2026-10-23. Applies to the current Colyseus0.18 SDK and presentation6/build carwars-ws-6; physical phone and WAN budgets are outside this evidence.

A pending SDK admission can resolve after the UI cancels. A room-reference guard alone is insufficient before that room exists. RoomClient increments connectionEpoch before starting or cancelling; cancellation rejects the pending caller immediately. A late admitted room disables reconnect and leaves without installing presentation handlers. Every awaited welcome/map callback checks the current room before sending map-ready. Overlapping attempts cannot replace the latest one.

A snapshot-transfer reset on transport drop must keep its listeners for reconnect. listenSnapshots returns a reset function with a separate dispose method; final leave disposes both listeners, drops the bounded buffer and removes room signals. Before disconnect, stop sends neutral/halt while the socket and active actor still exist. Leave releases prediction, timers, gameplay/event history and frame buffer, then clears presentation city/props/models. Shared model assets belong to the page; cloned police/player geometry belongs to each visual.

HUD is a presentation of gameplay.players selected by local sessionId. It never advances an arrest/wanted FSM or runs gameplay transactions. Respawn after arrest sends the personal server command; it preserves the room map and other players. Non-authoritative prediction remains the chosen input architecture.

Final verdict remains in the task.

Independent QA found a further pinned-SDK detail on2026-10-24: disabling reconnection.enabled does not cancel an already scheduled retryReconnection callback in0.18.5. It can reopen a departed socket after all room listeners are removed. retireRoom also retires the public connection.reconnect method and closes CONNECTING transports. The SDK callback may still run once within its bounded delay, but cannot create another connection. Real SDK regression waits beyond the retry delay and then verifies a fresh join. No global timer hooks or node_modules edits are used. [Original QA reproduction](multiplayer/2026-10-24-client/qa/reconnect-cancel.json).

The next independent QA found a stale asynchronous error continuation: old leave acknowledgement could arrive after a fresh connection and overwrite its phase. Guard connectionEpoch again after awaited teardown, not only before it. Also invalidate a separate welcomeEpoch on drop/leave/new welcome; a previously completed transfer can still have an async welcome callback in flight after the transfer buffer was reset. Real SDK tests cover paused old TCP leave acknowledgement followed by fresh join, and two drops while an older welcome callback is awaiting presentation. Verified8/8 optimized Node22 on CPU0,2026-10-24; full-suite receipt and final QA stay in the task.

Further independent QA,2026-10-24: counting live player meshes to name a new friend duplicated the survivor label after3→2→3. Allocate the first free friend ordinal among live visuals, release on disposal and use distinct label backgrounds. A cold connection also exposed inherited base-room patch/simulation timers firing while hosted onCreate awaited map readiness. Stop inherited timers synchronously before that await; start hosted cadence only after verified map/state/metrics and reset the elapsed-time accumulator. A delayed250ms map-readiness SDK regression checks no premature callbacks/ticks and102 civilians after playing. Focused optimized Node22:10/10; final acceptance stays in the task.

The full Linux check and a fresh independent QA on2026-10-24 exposed a remaining startup clock error: Colyseus clock.currentTime still predated async map preparation. Its first tick charged cold initialization time to a newly scheduled loader timer (an1800ms deadline fired about6ms after admission with forced3000ms initialization). Start the room clock together with hosted cadence after readiness; resetting only the physics accumulator does not reset SDK delayed timers. A disposable single-CPU Linux probe restored the existing map-ready test without increasing its deadline. The stronger regression uses2500ms readiness,1600ms admission deadline and250ms asynchronous presentation.
