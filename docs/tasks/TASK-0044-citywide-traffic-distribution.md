## 4. Требуемое поведение

- Удалить центральный cutoff: кандидаты берутся из всей пригодной дорожной сети; спавнить только на корректных проезжих участках.
- Предложение автора: распределять очередь по доступной длине направленных полос в пространственных секторах, затем round-robin/seeded выбор внутри сектора. На карте по умолчанию измерять 3×3 сектора по bounds; крайние сектора с дорогами получают машины. При count меньше количества секторов не требовать машину в каждом.
- При default60 и свободных дорогах после заполнения очереди число машин в каждом секторе отклоняется от квоты по длине полос не больше чем max(2 машины, 25% квоты). Это предложенная автором проверка стартового размещения, не требование равных мгновенных чисел на каждом перекрёстке.
- Небезопасный сектор не блокирует заполнение остальных: перераспределять доступные места и сохранять pending count для дефицита; не ослаблять isTrafficSpawnSafe. Позже освободившиеся окраины снова участвуют.
- reset, повышение count, изменение roadWidth/rebuild используют ту же стратегию. Seed воспроизводим; нет телепортации уже едущих машин ради ровного histogram.
- После 300 с окраины должны оставаться посещаемыми маршрутами, а offscreen машины продолжать движение. Показать occupancy/travel по секторам; если routing даёт устойчивый перекос, исправить выбор целей в этих границах.
