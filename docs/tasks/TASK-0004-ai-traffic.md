## 1. Цель и запрос пользователя

Исходный запрос: «о создании системы трафика из других машин».

Цель — добавить в свободную езду другие движущиеся автомобили, чтобы мир воспринимался населённым и с ними можно было разделить пространство движения. Сейчас сцена создаёт один визуальный автомобиль, а `CarSimulation` симулирует только его; других машин, маршрутов и логики трафика нет.

Предложение автора для первой версии: несколько визуально отличимых автомобилей ездят по заранее заданным замкнутым/циклическим маршрутам с плавным рулением и регулированием скорости; для первой версии они не сталкиваются с автомобилем игрока и не участвуют в физической симуляции. Это снижает риск повредить текущую модель, но может не соответствовать ожиданию взаимодействующего трафика и потому требует подтверждения.

## 3. Область изменений

- Одна цель: первая работоспособная система нескольких управляемых алгоритмом автомобилей, заметных во время свободной езды.
- Предварительно затронутые файлы: `src/main.js`, `src/vehicle.js` только если выбранная модель требует новых тел/общего шага, один новый модуль логики трафика в `src/`, возможно тесты, `README.md` и `VERIFICATION.md`.
- Не включать дорожную карту/процедурный город, пешеходов, светофоры, правила дорожного движения, повреждения и миссии.
- Не менять управление игроком, камеру, настройки подвески, шины и следы.
- Для автономных маршрутов использовать локально определённые пути/waypoints; задача не должна зависеть от выполнения TASK-0003. После появления генератора города маршруты можно будет заменить отдельной работой.
- Не добавлять внешние модели и сетевые зависимости без согласования.
- Зафиксированное решение для первой версии: шесть видимых упрощённых автомобилей, без физических столкновений между собой и с игроком; они повторяют замкнутый маршрут по центральным дорогам со скоростью 6.5–7.75 м/с. Сброс возвращает все машины к исходной фазе маршрута. Реакция на игрока, обгон и светофоры не входят в этот этап.

## 4. Требуемое поведение

Целевой сценарий: после загрузки игры в окружении видны несколько других автомобилей. Они движутся плавно и повторяемо, держатся назначенных маршрутов, не телепортируются в поле зрения и не мешают сбросу/управлению игроком. Машины имеют ограниченную максимальную скорость и не накапливаются в одной точке.

Кандидатная первая версия (требует подтверждения в разделе 8):

1. От 3 до 6 автомобилей с ограниченной областью появления вокруг игрока; количество фиксированное и управляется константой.
2. Детерминированный набор замкнутых маршрутов, построенный по локальным waypoint-узлам, пригодных для тестов без WebGL.
3. Машина направляется к следующему waypoint с плавным изменением курса, останавливается/перестраивается при чрезмерном отклонении от пути и регулирует скорость по кривизне/дистанции до waypoint.
4. Модели/варианты имеют визуальные отличия по цвету или кузову. Если повторно используется GLTF, его загрузка не блокирует управление и не создаёт гонку с загрузкой модели игрока.
5. Выбранная версия не должна порождать физические столкновения: уточнить, допускается ли отсутствие коллизий с игроком и между NPC. Если предполагаются коллизии, специфицировать их и интегрировать так, чтобы расчёт и `world.step(dt)` происходили ровно один раз за физический тик.
6. При потере видимости или выходе далеко за пределы активной области машины корректно возвращаются на маршрут или удаляются/создаются с ограниченным количеством объектов. Появление не должно происходить рядом с машиной игрока или внутри неё.
7. Reset игрока оставляет число машин постоянным и не создаёт копий. Нужна фиксация — сохраняется ли их позиция/фаза маршрута или трафик также возвращается к seed-состоянию.

## 7. Проверки

### Автоматические

Из корня проекта: `npm test`, `npm run build` (или `pnpm test`, `pnpm build`). Ожидаются успешные тесты и production-сборка. Тесты чистой маршрутной логики должны покрыть повторяемое продвижение по прямому и замкнутому маршруту, прохождение waypoint, нулевой/большой dt согласно договору, ограничение скорости и конечность состояния при некорректных входных данных. Если добавлены физические коллизии, соответствующие автоматические тесты должны подтвердить однократный fixed step и отсутствие дублей тел после reset.

### Ручные — обязательные

1. Запустить `npm run dev`, дождаться загрузки; убедиться, что несколько машин видны и не перекрывают старт игрока.
2. Ехать за NPC и поперёк маршрута, двигаться по прямой и делать резкие повороты. Проверить плавность, прохождение waypoints, отсутствие телепортаций, зависаний и неконтролируемого накопления машин.
3. Нажать `R`/«Заново» несколько раз: число машин остаётся постоянным, игрок сбрасывается, трафик следует выбранному правилу; утечек/дубликатов нет.
4. Проверить клавиатуру и плавающий указатель, высокое и лёгкое качество, широкий и узкий экран. С `#debug` записать FPS/CPU/draw calls до и после при сопоставимой сцене; не задавать гарантию конкретного FPS.
5. Если выбран физический контакт — отдельно проверить касание машины NPC, поведение игрока, стабильность физики и невозможность застрять/подбросить автомобиль.

## 8. Предположения, вопросы и условия остановки

**Проверенные факты:** сейчас в сцене один автомобиль игрока; физическая модель игрока находится в отдельном `CarSimulation`, который владеет собственным `cannon-es World`. Фиксированный шаг равен 1/120 секунды. Wheel raycast машины фильтрует объекты маской 1; добавление чужих физических тел требует аккуратно сохранить эти фильтры.

**Зафиксированные решения для первой версии:** шесть локальных визуальных автомобилей на замкнутом маршруте через координаты ±15 м; скорость 6.5–7.75 м/с; без физических столкновений и реактивной логики; после reset позиции восстанавливаются по фиксированному seed-маршруту. Маршрут не читает данные генератора и не создаёт дополнительную физику.
