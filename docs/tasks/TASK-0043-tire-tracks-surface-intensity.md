## 4. Требуемое поведение

- Предложение автора: два независимых контрола «Порог заноса» (множитель чувствительности порогов, 0.5–3, шаг 0.05, начальное значение подобрать по реальным сценариям) и «Интенсивность следов» (0–1, шаг 0.01). Первый управляет появлением, второй прозрачностью; 0 интенсивности не должен создавать невидимую геометрию.
- Сохранить отдельные start/continue пороги, подтверждение и release, непрерывность, 45-секундное исчезновение и bounded buffer. Ни угол руля, ни факт поворота сами по себе не запускают след.
- Обычный поворот без заметного сноса должен оставаться чистым при дефолтах. Сначала измерить реальные lateral/longitudinal/load/slip и движение кузова; синтетический wheel fixture не доказывает отсутствие ложного срабатывания. При необходимости уточнить детектор с использованием реального сноса, не глушить эффект одной прозрачностью.
- Высоту определять по тем же прямоугольникам покрытий, что рисует город, с небольшим depth offset. Хранить Y у сечений и торцевого fade; переход дорога↔тротуар не создаёт длинной висящей/утопленной полосы. Проверить обе стороны полосы на границе покрытий. Данные поверхности обновляются после rebuild.
- Отрыв колеса, отсутствие контакта, reset, отключение эффекта и скачок положения разрывают полосу. Невалидные настройки дают безопасный fallback, старый storage-профиль загружается с новыми дефолтами.
