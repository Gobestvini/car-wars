## 1. Цель и запрос пользователя

Исходный запрос: «давай у всех переккретков на тротурах скруглим острые углы».

Сейчас поднятые тротуары подходят к пересечениям прямоугольными углами. После изменения обращённые к перекрёстку выступающие углы имеют плавную дугу; светлая кромка и физический бордюр повторяют её. Машина может проехать по освобождённому месту без невидимого старого угла.

Решение автора: скругление срезает угол внутрь существующего footprint, не расширяет тротуар на полосу дороги. Радиус по умолчанию 2 м, ограниченный шириной тротуара и доступными длинами соседних сторон; минимум 8 отрезков на четверть окружности. Пользователь точные размеры не задавал. Скруглять фактические внешние углы объединения тротуаров у пересечения дорог, включая крайние перекрёстки; не углы каждого технического tile.

## 4. Требуемое поведение

1. Единый источник контуров: сначала объединение существующих sidewalk tiles, затем скругление только выпуклых углов, у которых обе соседние стороны выходят к двум пересекающимся дорогам. Поиск привязать к геометрии road centres/roadNetwork, не к фильтру degree=4 у светофоров. Не делать вырезы на швах tile и произвольных границах карты/plaza.
2. Для каждого такого угла четверть окружности касается обеих прежних прямых кромок. Радиус `min(2 м, sidewalkWidth, половина каждой доступной соседней длины)`; при нулевой ширине или вырожденной длине ничего не создавать. Отрезки соседних дуг не пересекаются. Выбранный радиус и сегментация одинаковы в high/low, чтобы физика не менялась от качества.
3. Поверхность, боковые грани, cap и физические опоры используют один и тот же полигональный контур. Не оставлять полный старый box под срезанным углом. В освобождённом участке добавить непересекающийся асфальтовый patch на y=0.005, согласовать road membership/height sampler, без наложения на сохранившийся тротуар и без z-fighting.
4. Предпочтительный путь: прямые части сохраняют локальные boxes; затронутые углы разбить на выпуклые polygon prisms с `C.ConvexPolyhedron`, верх 0.15 и низ −0.015. Добавить минимальный API опорной формы с тем же bookkeeping, material, group=1, `wheelSupport` и удалением, что у boxes. Допустимо равноценное разбиение, если погрешность footprint относительно визуального контура ≤0.02 м и отсутствуют перекрывающие вырез bodies. Не собирать весь город в один гигантский collider.
5. Sampler возвращает sidewalkVisual только внутри нового контура, road height в срезанном участке; offset сохраняет смысл. Следы шин лежат на правильной поверхности на дуге/за ней. Посадка дерева проверяет новый footprint с радиусом корня; стойки светофоров не оказываются над асфальтом. При выбранном радиусе текущие позиции стоек должны сохраняться; если обнаружен конфликт, сначала уменьшить радиус конкретного угла, не передвигать stop line/маршруты.
6. Во всех кварталах и на крайних пересечениях нет острых выступов у дорог, щелей, наложений кромок, двойных внутренних стенок или треугольников с неверной нормалью. Машина заезжает на оставшийся бордюр и опирается на тротуар как раньше; проезд по срезанному уголку идёт на уровне дороги.
7. Rebuild 12→15→30→12 не копит геометрии/тела; disposal удаляет polygon supports и old meshes. Количество draw calls остаётся батченым по существующим материалам, не один Mesh на каждый отрезок дуги.
