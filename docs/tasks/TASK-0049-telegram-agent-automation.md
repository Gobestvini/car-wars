## 1. Цель и запрос пользователя

Пользователь смотрит игру с телефона, пишет правки боту. gpt-6.1-sol исследует проект и оформляет задачу через create-task, gpt-6-luna выполняет, при сбое или failed/blocked помогает gpt-6.1-sol. Результат, вопросы и ссылка на игру возвращаются владельцу в Telegram. Сейчас такой интеграции нет.

## 4. Требуемое поведение

- Без сторонних runtime-зависимостей: Node fetch, fs, child_process. Секреты и состояние вне Git; токен не передавать модели/в логи.
- Привязка владельца через локально сгенерированный случайный одноразовый код /pair CODE; только личный чат. После привязки команды принимает только владелец. Не использовать принцип «первый написавший становится владельцем».
- /help, /status, /game, /pause, /resume; текст — правка, /reply ID TEXT — уточнение blocked-запроса. Фото с подписью поддержать через getFile и --image, либо явно сообщать о неподдержанном формате; голос/видео не терять молча.
- Durable JSON очередь и offset: сначала записать вход, потом подтверждать getUpdates. Отдельный poll и последовательный worker; новые сообщения и /status доступны во время работы. Блокировка единственного экземпляра; ошибки сети повторять с задержкой. После аварийного завершения running перевести в состояние, требующее явного повтора, не исполнять автоматически повторно.
- Каждая правка в отдельном git worktree/ветке codex/telegram-ID. Перенести пользовательские инструкции AGENTS.md и локальные навыки, исключить их из коммита. Общие зависимости node_modules можно связать junction. Не менять основной checkout во время работы моделей. Не запускать при посторонних локальных изменениях игрового кода (AGENTS.md/.agents разрешены).
- Planner строго gpt-6.1-sol, исполнитель gpt-6-luna, fallback строго gpt-6.1-sol. Структурированные финалы через output-schema: planner ready/blocked с taskPath и вопросом; worker done/blocked/failed с summary/question. Нулевой exit сам по себе не означает успех. Проверить taskPath внутри docs/tasks/TASK-*.md. Модельные промпты требуют find-skills, create-task для planner, актуальный код, отчёт/INDEX и обязательные проверки. Системный оркестратор управляет commit/push, агентам явно запретить commit/push и чтение секретов (переопределение проектного правила только для этого управляемого запуска).
- По завершении done провести node:test и Vite build в worktree. Если проверка не проходит — один вызов fallback, затем повтор проверок; при повторном провале остановиться с отчётом, не публиковать.
- Коммит только изменений из worktree с исключением скопированных AGENTS.md/.agents. Перед переносом проверить, что текущая ветка/HEAD основного checkout не изменились и нет новых локальных игровых изменений; merge --ff-only, git push текущей ветки. При ошибке push сохранить commit и сообщить. Не force push, не reset/clean. При конфликте сохранить ветку и сообщить.
- Возвращать ссылку https://gobestvini.github.io/car-wars/ и честно сообщать, что публикация GitHub Actions после push ещё может идти.
- Windows start.ps1 с проверкой Node/Codex, скрытый фон по отдельному флагу, локальный журнал/PID, stop.ps1. Пример env и понятная инструкция BotFather, pairing, команды, работа только при включённом компьютере. Не регистрировать автозапуск без необходимости.
