## 4. Требуемое поведение

- Автор конкретизирует «реальный AI» как local planner/controller: oriented lane graph с правосторонним движением, seeded destinations и A*/Dijkstra/эквивалент, переходы straight/left/right. После прибытия другая достижимая цель; не общий ring и не random coordinates вне дорог.
- Контроллер выдаёт steer/throttle/brake/handbrake с учётом speed/кривизны. World задаёт позицию; единицы внутренних скоростей м/с, telemetry документирована.
- Учитывать игрока/лидера/препятствия и относительную скорость; держать дистанцию, остановиться до стоящего объекта в controlled scenario.
- Автор предлагает deterministic reservation конфликтной зоны на пересечении с tie-break по id. Не впускать конфликтующие маршруты одновременно; освобождать reservation при выходе, удалении, аварии/timeout без въезда вслепую.
- Состояния following/yielding/arrived-replan/stuck-recovery. После удара переоценить segment/path; recovery через inputs, без visible teleport/отмены импульса. Недоступный путь → безопасная остановка и bounded retry.
- Count=0/1/30, удаление и пересборка города не оставляют graph references/reservations. Debug id/goal/route/state и deterministic seed для проверки.
- Planning по событиям, perception/control 10–20 Hz (предложение автора), inputs кэшируются, физика 120 Hz. Пространственный поиск соседей, без O(N²) scene raycasts каждый physics tick.
