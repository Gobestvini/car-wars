## 1. Цель и запрос пользователя

Исходный тезис: «После столкновения с препятствиями они сразу должны быть исключены из физики стать полупрозрачными … уход в альфу». Уточнение: «нет не бот а это про объекты на тротуарах»; «Сбитые препятствия».

Сбитый предмет на тротуаре сразу перестаёт быть препятствием для машин и других тел, становится полупрозрачным и быстро исчезает через opacity. Боты при этом не исчезают. Одинаковое правило действует в online и offline через общий модуль объектов.

Сейчас при разрушении статическое тело заменяется динамическим, остаётся в solver до 5 с и в последние 0.5 с визуально уменьшается. После изменения остаётся только краткий визуальный след без физического тела и уменьшения размеров.

Предложение автора для однозначного исполнения: сохранить действующие пороги разрушения; в момент перехода `intact → detached` opacity=0.45, затем линейное затухание до 0 за 0.75 с симуляции, без непрозрачной паузы. Числа — настройка автора, а не дословное требование пользователя.

## 4. Требуемое поведение

1. При существующем достаточном для разрушения ударе сразу перейти в detached. После обработки перехода в этом же физическом шаге в World/контактных кандидатах нет ни исходного, ни заменяющего тела предмета. Он не толкает, не тормозит и не повреждает машины, не участвует в raycast-подвеске. Если разрушение определилось после solver, уже состоявшийся первый контакт допустим; следующего нет.
2. Состояние detached остаётся для возраста/репликации. `body` можно сохранить как данные позы вне World; `byBody`, `activeIntact` и повторная активация intact-объектов не возвращают его в физику. Новую симуляцию падения/полёта не вводить: для этой задачи допустима фиксированная поза в момент разрушения и короткий fade на месте.
3. С первого отображённого кадра после разрушения весь предмет имеет alpha≤0.45; alpha монотонно идёт к 0 за 0.75 с симуляции. При alpha>0 исходный размер не меняется. В конце — removed и полное отсутствие визуального следа; frame dt и pause не продлевают физический lifetime.
4. Для локальной прозрачности использовать визуальный proxy сбитого предмета: скрыть его исходные slots, переиспользовать geometry, иметь независимые материалы прозрачности. Активных proxy не больше `PROP_DEBRIS_LIMIT=24`; idle-кеш тоже ограничить 24 записями. По лимиту удалять самый старый ghost, как сейчас. Не создавать mesh/material для каждого целого предмета.
5. Все части одного объекта исчезают согласованно; соседние instances, другие деревья/линзы остаются непрозрачными. Уничтоженный светофор сразу гасит свой световой эффект; переключение качества/фазы не возвращает его.
6. Сервер, prediction и restore используют один lifecycle. Rewind в intact восстанавливает исходный предмет; restore в detached никогда не добавляет тело в World, сохраняет возраст/opacity; removed не оживает при late join/reconnect. Повторный кадр/контакт не продлевает fade и не дублирует события.
7. Сохранить формат стабильных IDs и ограниченность snapshots. Поскольку смысл detached изменён, согласованно обновить presentationVersion для online-клиента, hosted-сервера и его smoke/probe/test клиентов. Не менять map/binary version без изменения их фактического формата. Старый клиент получает существующее сообщение об обновлении.
