## 4. Требуемое поведение

- Предложенная архитектура: один владелец World/ground/materials/staticBodies; CarSimulation принимает world/spawn, разделяет force step и post-step. Все авто используют одни формулы подвески/шин/руля/тормоза/сопротивления; настройки игрока и базовые NPC могут храниться отдельно, solver общий.
- Каждый tick 1/120: inputs всех авто → силы всех авто → world.step(STEP) ровно один раз → синхронизация/контакты всех авто. Поддержать standalone single-car tests либо адаптировать к явному World без ослабления регрессий.
- NPC dynamic bodies в том же world, не kinematic оболочки и не отдельные worlds. Контакты игрок↔NPC/NPC↔NPC/NPC↔здания передают импульс; фильтры wheel rays исключают своё шасси/непредназначенные поверхности.
- Контроллер только выдаёт inputs, не переписывает body transforms после удара. На этом этапе допустим временный контроллер прежнего маршрута через inputs; route positioning напрямую запрещён.
- Сохранить damage/отрыв колёс/reset игрока; подробная визуальная деформация NPC не обязательна. Коллизионные размеры NPC совпадают с оболочкой; low-poly визуал допустим.
- trafficCount в Tweakpane: предложение автора 0..30, integer step=1, default=6. Менять на границе tick; spawn свободен от игрока/NPC/зданий. При нехватке мест отложить spawn и отображать фактическое/pending количество в панели/debug.
- Удаление очищает тела/listeners/meshes/ресурсы/detached wheels. Reset возвращает заданное count, count=0 работает, NaN/out-of-range валидируются. carLab.traffic() сохраняет x/z/heading/speed с указанными единицами.
- Сразу исключить отдельный world на NPC, world.step на каждый instance, крупные per-frame аллокации. Глубокая оптимизация следующая; физику игрока не подменять ради FPS.
