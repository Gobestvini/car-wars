## 1. Цель и запрос пользователя

Запрос: «переделать эффект миниатюры c помощью блюра по референсам». Пользователь приложил три фотографии, они сохранены без изменения в `docs/art/references/2026-10-09-miniature/`:

1. `01-intersection.png` — резкие машины/пешеходы в средней части, сильнее размытые дальние здания и ближний край.
2. `02-street.png` — компактная резкая область действия, мягкое размытие переднего и дальнего планов; нет резкой границы фильтра.
3. `03-city.png` — эффект игрушечного города за счёт выборочной резкости, плавно уходящей к верхнему и нижнему краям.

Нужен выраженный tilt-shift эффект: чёткая область действия в середине кадра и постепенное увеличение радиуса размытия к ближнему/дальнему краю. Сохранять читаемость машины и дорожной ситуации. Референсы задают характер фокуса и размытия, не новую архитектуру города, текстуры, палитру, виньетку или чёрные поля первого PNG.

## 4. Требуемое поведение

- При заводских настройках эффект сразу заметен в follow: центр резкий, ближний и дальний планы мягкие; радиус растёт плавно с удалением от центра. Не сохранять старую схему только как mix резкого изображения с одним фиксированно размытым кадром.
- Решение автора: горизонтальная screen-space полоса с центром Y=50%, default резкой зоны 40% высоты; текущий диапазон 20…90% сохранить. Не копировать наклон отдельных фотографий: в движущейся игре выбран стабильный горизонтальный фокус без нового UI наклона.
- Начальные ориентиры для максимального радиуса при strength=1: high 18 CSS px, low 12 CSS px. Это художественные стартовые значения автора, допускается настройка по реальному рендеру с записью финальных значений и причины. В резкой зоне радиус 0; плавный переход занимает оставшееся расстояние до верхнего/нижнего края. Strength управляет радиусом отдельно от размера зоны, 0 даёт прямой рендер.
- Радиус в CSS px не зависит от DPR; mask в долях высоты кадра не следует за зумом/скоростью/проекцией машины. При изменении ориентации окна полоса сохраняет долю высоты, а эффект остаётся заметным и играбельным. Центр действия и машина в обычной follow-камере читаются; при конфликте сначала настроить ширину/плавность, не менять камеру.
- Сохранённые корректные strength/focusSize профили применяются без сброса: default 40% получают только новые/неполные профили. Проверку нового default выполнять с очищенным ключом или сбросом настроек; профиль со старым значением 68% не является ошибкой миграции.
- Нет двойных резких контуров на размытых зданиях/машинах, полос перехода, размытия только по одной оси, мерцания при движении, чёрных краёв, грязных ореолов или выцветания. На постоянной цветной заливке blur не меняет цвет. Tone mapping/sRGB выполняются один раз в конце линейной цепочки.
- Low/high различаются вычислительной стоимостью, но сохраняют один характер эффекта. Resize/quality/strength/focus не создают ресурсы каждый кадр; fallback всегда оставляет рабочую сцену.

## 5. План для исполнителя

1. Просмотреть три PNG рядом с текущей игрой. Снять baseline со сброшенными настройками, одинаковыми seed/камерой; проверить blur off/on и существующие GPU color tests.
2. Заменить единственный fixed blur уровневой цепочкой: sharp + три последовательных уровня возрастающего размытия, separable Gaussian по двум осям с downsampling. Для пикселя получить желаемый радиус из плавной screen-space маски и интерполировать два соседних уровня. Рассчитать накопленные эффективные радиусы (для Gaussian дисперсии складываются), чтобы переходы между уровнями не давали скачков резкости. Равноценный bounded подход с переменным радиусом допустим при тех же визуальных/ресурсных критериях.
3. Ограничить число уровней/проходов, использовать существующие quality scales как отправную точку; не рендерить геометрию заново для каждого уровня. Размеры и offsets учитывать в координатах конкретного target и CSS px. Сохранить линейные targets, единичную выходную конверсию, MSAA и восстановление renderer state.
4. Подключить default focus 40% и именованные quality radii. Сохранить публичный effect API и debug controls; расширить snapshot уровнями/размерами/оценкой памяти, если изменились ресурсы. Проверить настройки без пересоздания targets и обратную совместимость профилей.
5. Добавить содержательные unit checks маски/радиусов и GPU fixture с частыми контрастными деталями в центре/переходе/краях. Адаптировать существующие runners, а не требовать старое фиксированное число passes. Сравнить before/after, проверить движущуюся сцену и стоимость, заполнить отчёт.
