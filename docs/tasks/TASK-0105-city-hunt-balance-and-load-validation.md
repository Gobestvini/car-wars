## 4. Требуемое поведение

Матрица и бюджеты из docs/knowledge/city-hunt-mode-design.md обязательны. Проверять новый полный mode, не reducedAI spike. В отчёте отделить тесты от браузера, touch viewport от real device, номинальную частоту от measured, developer evidence от независимого QA.

1. Runner создаёт настоящую city-hunt комнату: один город, три гонщика, 102 civilian NPC. Максимальная нагрузка: 6 police, 2 barriers, 2 strips, 1 signal override и 1 intercept order. Не создавать четвёртую player body и не уменьшать population ради pass. Выполнить минимум пять полных раундов по 120 с после прогрева; исходы city-all-captured и racers-timeout дополнительно воспроизвести контролируемыми fixtures и наблюдать в UI.
2. Провести пять игровых проб с разными стратегиями города и гонщиков: записать captures по времени, расходы энергии, применение карт, rejected targets, время без действий и причины победы. Scripted drivers допустимы для воспроизводимости; отдельно проверить обе роли интерактивно через настоящий UI. Наличие отдельной группы людей не является условием запуска. Не объявлять баланс доказанным ботами или пятью матчами и не обещать 50% win rate. Численные cooldown/cost/lifetime менять по сравнению before/after в config с соответствующими тестами; правила матча без решения не менять.
3. На объявленных hardware/runtime измерить substep p95 ≤ 6 мс, p99 ≤ 8.33 мс, wire ≤ 150 KiB/s для каждого из четырёх клиентов, bounded queues, heap и фактические physics/scheduler/patch cadence и debt. City render: desktop median ≥ 30 FPS, low/high отдельно с screenshot/trace; desktop не подтверждает mobile performance. Physics зоны остаются union racer bodies; не снижать трафик и не скрывать части города ради результата.
4. Сетевая матрица: RTT 0/50/100/150 мс, jitter 20 мс и 1% packet-level loss/retransmission через настоящую impairment среду. На RTT 100 целевой input-to-visible p95 ≤ 200 мс для гонщиков; для карт отдельно измерить command RTT, server accept, видимое предупреждение и точность activation time. Не включать предусмотренные 1.5 с telegraph в network latency. Пропуск JS messages не заменяет TCP loss. Проверить одинаковый deadline 120 с, resync без повторных effects/refund, disconnect 5/16 с для обеих ролей и server restart.
5. Проверить deadline races, idempotency, caps, physical placement и старый roundId. Снять профиль города отдельно от гонщика; измерить bodies/listeners/pool leases после 20 join/leave/dispose и 10 rematch cycles. Route closures, colliders, modifiers и signal overrides очищаются после expiry, reconnect и finish по правилам дизайна.
6. Документировать запуск режима, role URLs/codes, четыре клиента и self-host WSS поверх готовой TASK-0101, серверные rules/config и ограничения. Секреты и большие полные логи не сохранять. В базе знаний оставить компактный отчёт с агрегатами и ограниченными samples, без полного packet dump или истории чата.
