# Задачи CarWars

Здесь хранятся самостоятельные задания, подготовленные для передачи другой модели. Для их выполнения нужен доступ к проекту. Это файловая очередь; каждый файл описывает одну проверяемую цель.

## Структура

- `INDEX.md` — очередь, зависимости и краткое состояние.
- `TEMPLATE.md` — шаблон задания.
- `TASK-0001-short-name.md` — конкретная задача. Номер растёт, slug пишется латиницей. Файл не перемещается при смене статуса.

Текущая очередь находится в `INDEX.md`. Создавай задачи только по реальному запросу, без выдуманного бэклога.

## Статусы

`draft` — остались вопросы; `ready` — можно передавать исполнителю; `in-progress` — выполняется; `blocked` — требуется решение или зависимость; `review` — работа завершена исполнителем и ожидает отдельной проверки; `done` — все критерии и обязательные проверки выполнены.

Статус в файле задачи — источник истины. При изменении обнови также INDEX. Незавершённая зависимость или важный открытый вопрос не допускают статус `ready`. Отдельная проверка нужна только если она предусмотрена задачей; иначе исполнитель может поставить `done` после выполнения критериев.

## Подготовка

Вызови `$create-task` и опиши желаемое поведение. Автор читает текущий код, заполняет шаблон, фиксирует границы и проверки, добавляет задачу в INDEX. Большую работу разбивает на отдельные задачи с явными зависимостями. Каждое задание должно быть понятно без истории чата.

Пользовательские формулировки и рекомендации автора различаются явно. Неподтверждённые предположения помечаются; важных нерешённых вопросов в `ready` быть не должно. Шаги содержат конкретные точки входа, но допускают равноценное решение в пределах задачи.

## Передача исполнителю

Открой чат в этом проекте, выбери модель и отправь:

```text
Выполни docs/tasks/TASK-0001-short-name.md. Прочитай AGENTS.md и задание, проверь актуальность контекста, внеси изменения в указанных границах, проведи перечисленные проверки и заполни отчёт и статусы в задаче и INDEX.md.
```

Если передаёшь текст в другой среде, приложи перечисленные в задании файлы и необходимые ресурсы. Не запускай одновременно задачи, которые меняют одни и те же файлы, без согласования. Навык подготовки не создаёт и не отправляет сообщения в другие чаты автоматически.

## Карта проекта

Это ориентиры на момент создания системы. Перед подготовкой задания проверяй текущий код и `package.json`.

| Файл | Назначение |
| --- | --- |
| `src/main.js` | Three.js, сцена, камера, загрузка модели, цикл игры и интеграция управления |
| `src/vehicle.js` | cannon-es, симуляция автомобиля, подвеска и силы шин |
| `src/driving-input.js` | Направление движения, газ, тормоз и переход в задний ход |
| `src/joystick.js` | Геометрия джойстика, радиус и мёртвая зона |
| `src/style.css`, `index.html` | Стили и разметка интерфейса |
| `tests/*.test.js` | Проверки физики, джойстика и управления через node:test |
| `public/models/` | Модель автомобиля и лицензия |
| `README.md`, `RESEARCH.md`, `VERIFICATION.md` | Запуск, описание, исследования и предыдущие проверки |

Текущие команды: `npm test`, `npm run build`, `npm run dev`. В проекте есть pnpm lockfile; эквиваленты — `pnpm test`, `pnpm build`, `pnpm dev`. Если Node не найден, проверь существующий `start.ps1` и доступные зависимости среды. Не переустанавливай зависимости без необходимости.

Для изменений физики и логики управления обычно нужны релевантные тесты и сборка; для интерфейса — сборка и конкретная ручная проверка. Автор фиксирует необходимые проверки в задаче. Новые тесты оправданы изменением поведения, а не требованием заполнять шаблон. Не редактируй `node_modules/` и `dist/` вручную.
