# Управление CarWars через Telegram

Локальный listener принимает личные сообщения владельца и передаёт запрос через Codex CLI: план задачи — `gpt-6.1-sol`, выполнение — `gpt-6-luna`, при сбое — один повтор через `gpt-6.1-sol`. Текущий код игры открывается на [GitHub Pages](https://gobestvini.github.io/car-wars/). Компьютер должен быть включён, подключён к интернету, с работающими Node.js и Codex CLI.

## Настройка бота

1. В Telegram откройте `@BotFather`, выполните `/newbot`, задайте имя и username, сохраните токен.
2. Скопируйте `.telegram-bot.env.example` в `.telegram-bot.env` и внесите токен после `TELEGRAM_BOT_TOKEN=`. Этот файл и состояние исключены из Git.
3. Запустите `powershell -ExecutionPolicy Bypass -File .\tools\telegram\start.ps1`.
4. Локальный журнал покажет одноразовый код привязки. В личном чате с ботом отправьте `/pair CODE`. Код принимается только в личном чате и после первой привязки погашается.
5. Отправьте `/help`.

Фоновой режим: `powershell -ExecutionPolicy Bypass -File .\tools\telegram\start.ps1 -Background`. Код привязки будет в `tools/telegram/telegram.log`, ошибки — в `tools/telegram/telegram-error.log`. Остановка: `powershell -ExecutionPolicy Bypass -File .\tools\telegram\stop.ps1`. После перезагрузки компьютера запустите listener снова; установка автозапуска не выполняется.

## Команды

- Обычный текст ставит правку в долговременную очередь.
- Фото нужно отправить с подписью; изображение передаётся обеим моделям вместе с запросом.
- `/status` показывает очередь, `/game` присылает ссылку на игру.
- Для текущей задачи `/status` показывает этап, модель, время работы, путь задания и время последнего вывода агента. Бот также сообщает о переходе между подготовкой, Sol, Luna, помощью Sol, проверками и публикацией. Пока модель обдумывает решение, вывод может некоторое время отсутствовать; это не доказательство зависания.
- `/pause` останавливает запуск новых задач, `/resume` возобновляет очередь. Входящие правки во время паузы сохраняются; текущая работа продолжается.
- `/reply ID ТЕКСТ` добавляет ответ к заблокированному запросу и ставит его на повторную проработку.

Голос, видео и документы получают явное сообщение о неподдерживаемом формате. При аварийном перезапуске задача со статусом `running` становится `interrupted` и не выполняется автоматически повторно. После успешной реализации запускаются тесты и production build; публикацию выполняет GitHub Actions после отправки изменений в `main`/`master`, и она может занять некоторое время. Нулевой код завершения Codex без структурированного результата не считается успехом.

Очередь и состояние хранятся локально в `.telegram-bot.state.json`, журнал — `tools/telegram/telegram.log`. Listener единственный на экземпляр. Не переносите токен в команду или сообщение боту.

Окна моделей не появляются: Codex CLI работает в скрытом фоне. Промежуточные игровые изменения находятся в `.telegram-worktrees/telegram-*`; основной проект обновляется после успешных проверок и переноса результата. Вывод каждой модели сохраняется в `tools/telegram/job-ID.log`, например `job-1.log`. Служебное состояние, журналы и токен исключены из Git. При обслуживании можно явно продолжить сохранённую задачу в том же worktree после согласования его HEAD с основной веткой; обычный аварийный перезапуск по-прежнему не повторяет running-задачи автоматически.

Каждый запрос выполняется в отдельной ветке `codex/telegram-*` и каталоге `.telegram-worktrees/`. Оркестратор проверяет отчёт задачи, запускает тесты и сборку, коммитит только изменения рабочего каталога, переносит их через `merge --ff-only` и отправляет текущую ветку в `origin`. Скопированные локальные `AGENTS.md` и `.agents/` в коммит не попадают. Если основная ветка или код изменились параллельно, перенос останавливается; ветка с результатом сохраняется. При неудаче push локальный коммит остаётся и бот сообщает об ошибке. При блокировке можно ответить `/reply ID ТЕКСТ`: новая попытка получит исходный запрос, фото и сохранённое задание/отчёт.
